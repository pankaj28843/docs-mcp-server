## Known limits and official fallbacks

- Current Boto3 and Botocore URLs can change the displayed SDK version without changing the URL. Check the fetched page title and compare it to the lockfile before applying version-sensitive behavior. Use the official [Boto3 documentation](https://docs.aws.amazon.com/boto3/latest/) and [Botocore documentation](https://docs.aws.amazon.com/botocore/latest/) directly if the local index is stale or lacks a service reference.
- The current Botocore index is 1.43.123, while TP Playbook locks 1.43.121. The official [1.43.121 source tag](https://github.com/boto/botocore/tree/1.43.121/docs) is the exact-version fallback for behavior that changed between patches.
- The `boto3` example configuration intentionally scopes AWS service references; a missing service result does not establish that Boto3 lacks that API. Use the official [service reference directory](https://docs.aws.amazon.com/boto3/latest/reference/services/index.html).
- The `botocore` example configuration also scopes AWS service references to S3 because the entire AWS service catalog is much larger than the TP Playbook data lane. Use the official [Botocore service directory](https://docs.aws.amazon.com/botocore/latest/reference/) for excluded services.
- The `postgresql` tenant is sourced from `/docs/current/`, which is not proof of PostgreSQL 16 behavior. Use the official [PostgreSQL 16 manual](https://www.postgresql.org/docs/16/) for version-specific checks.
- Private S3 safety requires checking the application's deployed IAM, bucket policy, Block Public Access, signed URL handling, and browser origin; documentation search cannot verify that deployment. The official [S3 access control guide](https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-management.html) is the source fallback.
